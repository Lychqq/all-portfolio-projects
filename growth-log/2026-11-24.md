## Real Artifact Verification vs Synthetic Mock Generation

### Context
When preparing screenshots for the developer portfolio, visual previews were needed for eight projects. The initial instinct was to generate synthetic standalone HTML mockups to capture images quickly instead of executing the actual project sources.

### Root Cause / Core Insight
Synthetic placeholders create low-fidelity representations that degrade credibility and misrepresent the actual codebase. When authentic application code, templates, and datasets reside directly on the local machine, fabricating fake markup violates verification integrity and wastes effort on maintaining disposable artifacts.

### The Pattern (transferable)
- Next time portfolio assets, documentation previews, or visual proofs are needed for local repositories, I will execute the genuine application services or render real source templates directly.
- Signal to recognize: Creating ad-hoc HTML files with mocked layout cards in temporary directories while genuine application codebases exist in adjacent local paths.

## Ephemeral Process Lifecycle for Automated Headless Capture

### Context
Automating multi-project screenshot capture with Playwright required spinning up local web servers (FastAPI/Uvicorn, Python HTTP server). Leaving these server instances active caused background resource consumption and held network ports open.

### Root Cause / Core Insight
Automated background dev servers spawned from CLI scripts lack automatic teardown hooks upon browser completion. Without an explicit termination protocol, child server processes become orphaned background tasks, consuming host RAM and causing subsequent port collision failures.

### The Pattern (transferable)
- Next time an automated test or capture script spawns local background servers, I will bind process lifecycles to deterministic exit handlers (try/finally blocks, explicit PID termination, or ephemeral context managers) that guarantee termination immediately after capture.
- Signal to recognize: Automated capture scripts invoking `subprocess.Popen` or background shell executions without explicit process termination or port-checking cleanup blocks.

## Difference Inversion Luminance and Viewport Collision Guarding

### Context
Replicating the Jorge Toloza kinetic typographic layout with a central orbiting text ring over scrolling parallax images, paired with a persistent project information card in the viewport corner.

### Root Cause / Core Insight
CSS `mix-blend-mode: difference` requires full white luminance (`rgb(252, 255, 254)` or `#ffffff`) to invert accurately against both dark and bright backgrounds; lower luminance or alpha values cause washed-out, illegible text over dark imagery. Furthermore, fixed overlays without vertical bounds (`max-height`) and safe bottom offsets physically obscure and block user interaction with fixed footer navigation links.

### The Pattern (transferable)
- Next time styling dynamic inverted text elements over heterogeneous media, I will enforce pure white color values for difference blending and establish explicit `max-height` constraints with reserved safe margins for corner overlays.
- Signal to recognize: Inverted text elements losing legibility over dark backgrounds, or fixed corner cards overlapping bottom navigation anchors on viewport resizing.
